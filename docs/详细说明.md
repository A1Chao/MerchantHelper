# 行商助手 · 战地行商外部感知辅助

> **作者：烟火**
>
> 《暗区突围：无限》"战地行商"玩法的**外部感知**辅助工具。
> 通过**屏幕截图 + 系统回环音频 + 独立悬浮窗**给出候选战利品参考，比参考样本多了一项核心能力：
> **自动识别拖动物品的占格与朝向**（样本需要用户手动选择 1/2/4/6 格）。

---

## 一、和样本的差异（我们更强的地方）

| 能力 | 样本软件 | 行商助手 |
|---|---|---|
| 拖动物品格数 | 需用户手动选「选择格数 1/2/4/6」 | **自动识别**（视觉锚定网格间距） |
| 朝向 | 手动选 横/竖/正 | **自动判定 H/V** |
| 候选数量 | 只给榜首 1 条 | **完整候选列表（默认 5 条）**，带置信度 |
| 候选内容 | 文本 | 缩略图 + 名称 + 品质 + 类别 + 参考价值 + 置信度条 |
| 手动筛选 | 有 | 有（品质/类别/朝向）+ 会话历史 |
| 触发方式 | 持续监听 + 热键 | **鼠标按下即触发**（P0 决策：不做全屏扫描、不做连续截图） |
| UI | Tkinter 主窗口 | **独立置顶悬浮小窗**，不抢焦点、不覆盖游戏 |

算法内核（梅尔频谱 + 多路匹配 + 波形互相关回退）与样本**逐指令一致**——样本的
`recognition.pyc` 已被完整反汇编重建（见 `docs/recognition_dis.txt`、`docs/接口契约.md`），
不是"猜测复刻"。

## 二、硬边界（本项目红线，代码级保证）

* **只读屏幕**（PIL ImageGrab），只在鼠标按下瞬间抓光标附近的小区域
* **只读系统回环音频**（WASAPI loopback，soundcard）
* **只读鼠标状态**（`GetAsyncKeyState` / `GetCursorPos`），**绝不写入**
* ❌ 不读游戏内存 ❌ 不注入进程 ❌ 不解包/修改游戏文件
* ❌ 不模拟键鼠（无 `SendInput` / `mouse_event` / `keybd_event`）
* ❌ 不自动点击、不自动购买、不自动交易
* ❌ 不联网、不自学习、不热更新；所有数据硬编码在 `assets/database.json`
* UI 是**独立悬浮窗**，不注入、不覆盖游戏画面

验收脚本会静态扫描全部源码，确保上述禁用调用不存在（`tests/selftest_integration.py` 第 0 项）。

## 五、使用

```powershell
# 1) 查看可选回环设备
D:\PY\python.exe main.py --list-devices

# 2) 运行（默认自动选择系统当前播放设备）
D:\PY\python.exe main.py

# 3) 指定设备 / 跳过占格识别 / 打开详细日志
D:\PY\python.exe main.py --device "扬声器 (2- Realtek(R) Audio)"
D:\PY\python.exe main.py --no-vision --verbose
```

**⚠️ 启动后默认是「未开始监测」**：此时**不截屏、不录音、不识别、不写任何文件**（避免在你没玩的时候
把别的应用截进去/录进去）。要点面板上的 **「▶ 开始监测」** 或按 **F8** 才开始；再点一次/再按 F8 停止。
想恢复"一启动就监测"的老行为：加 `--autostart`。

参数：`--pad`（截图半边长，默认 200）、`--pad-max`（高亮超出范围时自动放大，默认 400→800×800）、
`--capture-mode {auto,crop,full}`（auto=先裁光标周围、没拿到完整红块就整屏兜底，默认）、
`--log`（把控制台输出写文件）、`--save-shots`（存每次截屏，含整屏 `crop_N_90.png`）、
`--save-audio`（存每次触发的音频窗口）、`--limit`（候选数，默认 5）、`--settle`（按下后等待，默认 0.14s）、
`--min-interval`（触发最小间隔，默认 0.9s）、`--listen-max`（一次触发最多听多久，默认 2.0s）、
`--poll`（鼠标轮询，默认 12ms）、`--autostart`（启动即开始监测）。

**格宽（pitch）语义**（重要，2026-10 改版）：`--pitch 85` = **调用方权威值**，原样使用；
**不加 `--pitch`**（默认）= 每次触发都在**光标周围 270px 局部重测**（能量门 + 自洽打分 + 谐波守卫），
估不出来才回退常量 79 并明确标注「**常量回退(不确定)**」——
日志里写 `(局部自洽打分(support=N))` 才是真测到的值。`measure_grid_pitch`（整屏网格线）现在**只写日志**，
不再是格宽权威（旧版会把整屏统计值当权威，一旦被悬浮面板结构污染就会把毒值扩散到整场会话）。

**触发方式**：`--trigger mouse`（默认）只认鼠标左键；`--trigger audio` 只按"突起的短音效"触发，
**完全不依赖按键**；`--trigger both` 两者都开。若游戏以更高权限运行（反外挂常态），游戏内左键可能
**完全读不到**（日志会出现 `[env] 管理员权限 = 否` 与 `[hb] ⚠️ … 受理 0 次`）：
请右键**以管理员身份运行**，或改用 `--trigger audio/both`。
**光标落在本工具悬浮面板内的按下会被跳过**（`[skip] 触发落在面板内`），不计入识别——
测试时不要用面板按钮当游戏内按键。

**三个免命令行入口**（都在 `行商助手\` 下，内容为纯 ASCII，避免 cmd 代码页踩坑）：
`测试_只写日志.bat`（自动测格宽，只写文字日志、不录音不存图）、
`测试_固定格宽85.bat`（强制 `--pitch 85` 作权威）、
`测试_诊断触发.bat`（**需右键以管理员身份运行**；`--autostart --trigger both`，
用它一次定性"是鼠标被反外挂拦住，还是权限不足"）。

**选中锁定（2026-10 新增，用户反馈驱动）**：一次**按下**会开启一个「按下会话」——
按下那一刻起，程序就用**按下时鼠标所在位置**判定物品，并把**该会话首次成功的格数/朝向/来源锁定**；
此后同一会话里的按住续触、松开、甚至音频触发，都**不会**因为鼠标掠过别的物品而改写结果
（只会在日志里打一行 `[lock] …忽略当前位置的…`），**音频候选仍按最新声音实时更新**。
**重新按下 = 重新选目标**，锁定随之重置。这样"我选了 A"就不会变成 B。

**候选列表不会自己消失（2026-10 用户反馈修复）**：一次拖动其实会产生**多个触发**
（按下沿 / 按住续触每 0.9s 一次 / 松开），只有音效响的那一轮能匹配到候选，其余几轮听到的是
已经安静的窗口、判出"0 候选"——旧版这些"0 候选"会**无条件清空面板**，看起来就是
"拖动完过一会儿列表自己没了"。现在候选是**粘滞**的：**只有真正匹配到声音的新结果才会替换它**，
面板上只用「匹配于 N.Ns 前」体现新旧（秒数每次刷新实时计算）；点「清空」后**不会复活**。

**面板只给玩家看四类信息（2026-10 界面精简，作者 烟火 的要求）**：
1. **格数 · 朝向 · 来源**（例：`格数 2格 · 朝向 V · 来源 边框`）
2. **音频信息**：当前声音状态 `音频 44100Hz · <设备名> · 峰值 0.018`（看得出程序有没有在听）
3. **匹配于 N.Ns 前**（上次真正匹配到声音的时间，实时刷新）
4. **候选卡片**：72px 缩略图 + 品质徽章（金/红/紫填充色 + 自动对比色文字）+ 名称/品质/类别/格数
   + 参考价值 + **22px 粗体彩色百分比**（≥85 绿 / ≥70 黄 / ≥50 橙 / <50 灰；
   已与品质徽章色系区分，鼠标悬停提示"匹配概率（与品质无关）"）
   悬浮窗 440×820，可拖动（优先交给系统 `startSystemMove()` 移动），最多 20 条可滚动。

**诊断信息不在面板上出现**（本次原因、触发来源、格宽、锁定状态、左键"看到/受理"计数、管理员提示、
`[trace]` 类文本），它们**全部照旧写进日志文件**（`--log` 指定的路径，`_Tee` 是全局替换 `sys.stdout`/
`stderr`，所以面板代码打的日志也一定在文件里），排查时看日志即可。

**只显示与格数/朝向相符的候选（2026-10 用户反馈修复）**：一个音效键常常同时对应**多个物品**
（同音组），纯音频分不出是哪一个；视觉判出的**格数/朝向**是唯一能把它们分开的信息。
所以玩家面向默认**严格过滤**：视觉给出 `2格 V` 时，只显示 `2格 V` 的物品，
格数或朝向不符的**直接不显示**（只写进日志 `[filter] 丢弃 N 条与 2格V 不符的候选：…`）。
按形状筛完**一个都不剩**时，面板显示 `无与 2格V 相符的候选`，**不会**拿不匹配的物品来凑数。
需要对照旧行为时用 `--show-mismatch`（默认关，调试逃生门；也用于排查"真物品是否被误筛"）。

⚠️ **代价（如实声明）**：严格过滤的判据是"视觉格数/朝向"，**若视觉把格数判错，真物品会被一起藏起来**。
排查路径：`--show-mismatch` 当场对照 + 看 `[filter]` 日志里丢了谁、什么形状、多少分。
另有**残余不可分**：同音**且同形状**的物品仍会并列（例如 `金属声音` 的 2格V 有 5 个、
`硬币声音` 的 2格V 有 8 个）——纯音频 + 占格信息已无法再区分，需要更强的声音模型。

**面板右上角两个按钮（2026-10 新增）**：
* **`—` 收起 / 展开**：收起后面板压成一条 440×36 的细标题条（标题与两个按钮仍在），再点一次展开。
  **刻意不用 `showMinimized()`/`hide()`**——本窗口是无边框 `Qt.Tool`，没有任务栏条目，
  真最小化在游戏里找不回来；收起不挡视野且一键恢复。
  收起时 `screen_rect()` 同步变小，集成层的**面板屏蔽区**也跟着变小（pump 每轮刷新）。
  收起状态下 **F8 仍然有效**（F8 由集成层直接读全局键态，与按钮可见性无关）。
* **`✕` 关闭并退出**：关闭即**停止监测**（不再截屏/录音）并退出程序，等价于关窗。

**底部一栏只放检测状态**：空闲时显示 `未开始监测：不读取游戏信息，点上方按钮或按 F8 开始。`

**操作方式**：点「开始监测」或按 F8 → 在游戏里捡起/拖动物品的那一下（鼠标左键按下）→
悬浮窗自动给出候选列表。窗口可拖动，不抢焦点；筛选项可手动收窄结果；「清空」清候选，「历史」查看本次会话记录。

## 七、已知限制与有意差异

**拖动悬浮窗可能残留重影（2026-10 用户实测报告，修复待用户确认）**
* 症状：用鼠标拖动本工具的悬浮窗后，旧位置可能留下未擦除的残影，看起来像"两个界面叠加"。
* 机制（已定位）：无边框 + `setWindowOpacity(0.92)`（Windows 走 layered window）+ 圆角样式，
  而旧实现只在 `mouseMoveEvent` 里裸调 `move()`、**从不强制重绘或失效旧区域**。
* 现在的修法：拖动优先交给 **`QWindow.startSystemMove()`**（由系统移动窗口、旧区域自动失效），
  并在 `moveEvent` / press / release 各强制一次完整重绘；`windowHandle()` 取不到或平台不实现时
  **自动回退**到原来的手动 `move()`（回退路径已断言不抛异常）。
* ⚠️ **如实声明**：重影属 Windows 合成器层面的现象，**离线无法证伪**。自测只能证明
  "确实调用了 `startSystemMove`、无异常、几何正确"，**屏幕效果需用户实拖确认**；
  若仍有残影，下一步是"拖动时隐藏→移动→显示"。

**游戏内左键可能完全读不到（2026-10 实测发现，当前最主要的"用了没反应"原因）**
* 症状：进游戏按物品，程序毫无反应；日志里 `[hb] 左键 看到N/受理0` 的 N **不增长**，`触发0 候选0`，
  且整份日志**没有任何 `[pitch]`/`来源=`/`格数=` 行**（说明视觉代码一次都没被调用，不是"识别不准"）。
* 原因：本工具用**只读**的 `GetAsyncKeyState` 轮询鼠标左键。若游戏以**更高权限**运行
  （带反外挂的竞技游戏常态），普通权限进程可能读不到投递给高权限窗口的输入。
  **注意这是推断**：也可能是被游戏抢 CPU 导致漏拍，或因触发落在本工具面板内被跳过。
* 现在日志会**自己区分这三种原因**：`[env] 管理员权限 = 是/否`、`[hb] … 轮询最大间隔Nms 光标(x,y) 面板跳过K`，
  以及 `受理==0 且监测≥15s` 时的三支警告（完全读不到 / 只在点面板 / 发生在开始监测前或未达节流间隔）。
* 处置顺序：① 右键**以管理员身份运行**（入口 `测试_诊断触发.bat`）；
  ② 改用 `--trigger audio` 或 `both`（**音频触发不依赖按键**，对"拖动听声"的玩法更贴）；
  ③ 用轮询最大间隔区分"漏拍"与"读不到"。
* `--autostart` 可免去点面板按钮（避免"点的是我们自己面板上的按钮"这类混淆）。
* F8 热键**无法程序化验证**（自测只能验证 `set_active` 开关本身），需手动确认。

**游戏内丢帧（data discontinuity）—— 已修复**
* 症状：`SoundcardRuntimeWarning: data discontinuity in recording`，面板显示检测到拖动但没有候选。
* 原因：WASAPI 采集缓冲被读得太慢而溢出（丢帧）。样本用 soundcard 默认缓冲（=设备最小周期，约 10ms），
  余量极小；游戏吃满 CPU 时必然溢出。
* 修复（三处，均不改识别算法）：WASAPI 缓冲加大到 `BLOCKSIZE_SECONDS = 0.08s`；
  采集改 numpy 定长环（去掉逐样本 `deque.extend(block.tolist())` 的 GIL 开销）；
  采集线程提到最高优先级、识别线程降到 BELOW_NORMAL、整进程 ABOVE_NORMAL。
* 实测（`tests/probe_audio_under_load.py`，各 8 秒）：

  | 负载 | 修复前丢帧 | 修复后丢帧 |
  |---|---|---|
  | 真实识别负载 | 6 | **0** |
  | 20 个原生进程打满 CPU | 3 | **0** |
  | 无负载 | 0 | **0** |

* 若**仍然**丢帧，按顺序尝试：① 换 `--device` 到游戏实际播放的设备；
  ② 关掉游戏内录屏/回放/语音降噪，降低画质；③ 在 Windows 声音设置里取消该设备的
  "允许应用程序独占控制此设备"；④ 提高 `recorder.py` 里的 `BLOCKSIZE_SECONDS`（如 0.2，代价约 +0.1s 延迟）。
* 面板会显示累计丢帧次数（如「采集丢帧 12 次（CPU 争抢）」），控制台首几次也会打印 `[audio] 采集丢帧 第N次`。

**音效与背景的相对音量决定成败（游戏内最关键的设置）**
* 识别是"相似度"匹配，**信噪比**直接决定分数。实测（`tests/probe_e2e_debug.py`）：
  | 情况 | 背景 rms | 音效 rms | 撒币声音得分 |
  |---|---|---|---|
  | 环境安静 | 0.0018 | 0.008 | **97** |
  | 有很响的背景音 | 0.042 | 0.050 | **33**（无候选） |
* 因此在游戏音频设置里请**提高"音效/特效"音量、降低"音乐/环境音"音量**；游戏内录屏、语音降噪、
  音效增强（Realtek Audio Console / Windows"音频增强"）都建议关闭——它们会改变频谱，直接压低相似度。

**设备相关（最常见的问题来源）**
* 回环录的是**游戏声音实际播放到的那个设备**。本机当前系统默认是「耳机 (vivo TWS 5)」，
  若游戏声音走 Realtek 扬声器而工具听 BT 耳机，就会一直无信号。
  用 `--list-devices` 查看、`--device "设备名"` 指定；悬浮窗在长时间无信号时会给出提示。
* 仅支持"扬声器播放"路径（WASAPI 回环）；游戏使用独占音频模式时可能取不到声音。

**识别特性**
* **占格识别优先用"拖动红色高亮"**：拖动时游戏用实心暗红标出物品将要占用的格子，
  直接按红块尺寸算格数（实测 2×2 → `slots=4`、朝向「正」、置信度 0.9）。
  墙面/格子被裁切时红块不可信，会自动回退到"图标锚定 + 单格外框"的几何路径。
* 音频识别是**相似度**匹配，不代表真实出货概率；同音物品会同时出现（与样本一致，候选列表会全列出来）
* 占格识别依赖游戏 UI 网格间距（实测 79px）；分辨率/UI 缩放下可能失准，此时仍会显示音频候选
* 拖动物品被裁剪导致轮廓开口时，占格识别返回 `slots=0` + 中文原因（不猜），建议 `--pad 200`（默认值）
* 屏幕截图只在按下瞬间进行；游戏切到后台/最小化时无法识别

**与样本的有意差异（均已记录在 `docs/接口契约.md`）**
1. `match()` 返回 `output[:limit]`（完整候选）而不是样本的 `output[:1]`（仅榜首）——这是候选列表 UI 的前提
2. `recorder.listen_windows` 产出 **2 元组** `(window, background_rms)`（样本字节码是 3 元组，
   中间多一个 SAMPLE_RATE）；`main.py` 对两种元组都做了兼容解包
3. 占格检测用 `cv2.RETR_LIST`（样本资料若写 RETR_EXTERNAL 则不适用：`?` 图标嵌在格框内会被丢弃）
4. 算法内核（`_highpass` 两次级联 4 阶高通、`_scan` 早退与偏移列表、`_waveform_rank` 的 FFT 长度等）
   **全部以字节码为准**，优先级高于早期伪码
5. `recorder.py` 的健壮性改动：显式 `blocksize=0.08s`、numpy 环形缓冲、采集线程优先级、
   `discontinuities()` 计数（识别算法与 4 个契约常量未动，队友自测 15/15 仍通过）
6. 取样策略（`main.py`）：按下后若最高分 < 85，则按 `--retry`（默认 3）×`--retry-delay`（0.28s）
   继续取样并**保留分数最高的一组**。样本原本只在"未检测到声音"时重试。
   实测（同一次过早触发，`tests/probe_e2e_trigger.py --trigger-at 0.45`）：
   `--retry 0` → 0 候选；`--retry 3` → 撒币声音 **90~94 分**；正常时机触发 → **98 分，耗时 0.37s**。
   该策略只多听几个窗口，**不改 recognition 的任何阈值**。
